# Dannote: защищённый вход и команда King David

Подготовлено для существующего Firebase-проекта `kd-handover` и UID
`ScFdYFy3Tbc20j2k2caQfNIM7Zu2`.

Владелец управляет сотрудниками из кнопки с людьми в шапке приложения.
Профили синхронизируются через Firestore, поэтому одинаково работают на
разных компьютерах. Все сотрудники King David видят общие папки, дни и заметки.

## Установка

1. В GitHub-репозитории `ivanovdanial4-lang/KDhandover` замените `index.html`
   приложенным файлом с тем же именем и сохраните commit. Дождитесь публикации
   GitHub Pages. Не меняйте Firebase projectId и не удаляйте документы базы.
2. В Firebase → Firestore Database → Rules замените правила полным содержимым
   `firestore.rules` и нажмите Publish. Правила разрешают доступ владельцу и
   только активным профилям из `users` с `hotelId == "kingdavid"`. Сама
   регистрация Firebase без профиля доступ к заметкам не даёт.
3. Обновите сайт (Ctrl+F5). Введите отель `kingdavid`, логин `danila` и пароль,
   который создали в Firebase. Для текущего владельца приложение связывает этот вход с адресом
   `kingdavidfo@gmail.com`. Если аккаунт создан с другим адресом, нужно
   изменить это соответствие в `index.html`; UID при этом не меняйте.
4. Нажмите кнопку команды (иконка людей). В форме добавьте сотрудника: свой
   логин (например `anna`), имя, роль, цвет аватара и пароль не короче 6
   символов. Сотрудник входит с кодом `kingdavid`, этим логином и паролем —
   email ему не нужен. Кнопка Edit меняет имя, роль и цвет; ◌ приостанавливает
   доступ. Пароль после создания не отображается, сохраните его отдельно.
5. Проверьте старые папки и заметки. Нажмите Backup, сохраните JSON в защищённом
   месте. Экспорт читает все folders, days и вложенные notes, включая изображения
   внутри документов. Он не читает другие коллекции или Firebase Storage и не
   является согласованным снимком при одновременной записи.
6. Выйдите кнопкой Exit. В отдельном приватном окне проверьте, что без входа
   заметки не отображаются. В Rules Playground проверьте запрет чтения и записи
   без авторизации и с UID без профиля для путей folders/test, days/test и
   days/test/notes/test. Для UID владельца и активного сотрудника операции
   разрешены.

## Что сохранено

Пути документов и проект Firebase не изменены. Скрипта миграции или удаления
нет. Само открытие новой версии не переписывает заметки. Профили хранятся только
в новой коллекции `users`; старые папки, дни и вложенные заметки остаются на
своих местах. HTML старых заметок
очищается только для отображения; исходное содержимое остаётся в Firestore
до явного редактирования. Подозрительные HTML-элементы и внешние картинки
не отображаются. Имена старых авторов сохраняются при редактировании.

## Ограничения проверки и доступа

Проверки авторизации и DOM выполнялись с подменённым Firebase на синтетических
данных (Node VM и jsdom). Проверены вход, отказ чужому UID, выход, старые
заметки, очистка HTML, сохранение автора и даты, резервное копирование без
записи в базу и обработка ошибки сохранения. Полноценный браузерный тест
не запустился: браузер не установлен, загрузка завершилась тайм-аутом.
Настоящий пароль, содержимое рабочей базы и консоль проекта не использовались.
Правила необходимо опубликовать и проверить в вашем Firebase; они не были
развёрнуты или проверены через Firebase Emulator в этой среде.
Публикация GitHub Pages отсюда не выполнялась.

Вход хранится в сессии браузера. На общих ПК обязательно нажимайте Exit:
восстановление вкладок браузером может восстановить и сессию. Приложение не
включает постоянный офлайн-кеш Firestore; уведомления теперь только в памяти.
Старые локальные профили и уведомления удаляются из браузера при запуске.
Профили команды больше не хранятся в localStorage; пользовательские шаблоны
по-прежнему локальные, не храните в них данные гостей.
Ранее скачанные или скопированные посторонними данные отозвать невозможно.

## Важное ограничение

Кнопка добавления создаёт Firebase Auth-пользователя из браузера владельца
через отдельную Auth-сессию, поэтому отдельный платный сервер не нужен. Даже
если кто-то создаст сторонний Auth-аккаунт, без документа `users` и активного
`hotelId` правила не дадут ему читать заметки. Для публичных приглашений,
автоматического сброса пароля и нескольких отелей позже понадобится серверная
функция с Admin SDK (обычно тариф Blaze).

## Если обновление не работает

Временно можно оставить `allow read, write: if false;`, но приложение тогда
не увидит даже твои заметки. После проверки опубликуй именно `firestore.rules`.
Не возвращай `if true` и не выдавай доступ всем авторизованным пользователям.
