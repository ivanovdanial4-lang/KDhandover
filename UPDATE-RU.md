# Обновление KDhandover

Сайт сохраняет прежнее оформление и Firebase-проект kd-handover. Старые заметки остаются на прежних путях; их перенос не нужен. Старые записи без отдела отображаются как Reception.

## Что добавлено

- ☀️ в верхней панели открывает оригинальный пустой PDF для ручного handover.
- ☾ открывает печатную версию ночного чек-листа из Word. В превью нажать Print / Save PDF. Содержимое хранится в закрытом документе Firestore printTemplates/nightChecklist, поле paragraphs (массив строк), и загружается после авторизации. В публичный репозиторий оно не входит. Строка с данными входа UBYPORT заменена ссылкой на защищённое хранилище; исходный Word не изменён и в репозиторий не включён.
- Печать существующих задач: отдел, выбранный день/все дни, открытые/выполненные/все задачи.
- Отделы Reception, Housekeeping, Maintenance, Restaurant; упоминания сотрудников; закреплённые объявления над заметками.
- Check Tasks показывает незавершённые записи за все дни. Completed archive — завершённые записи, которые можно открыть заново.
- Напоминания через 3 или 5 дней внутри сайта. Проверка при загрузке и раз в минуту, пока сайт открыт и видим. Это не фоновые push-уведомления и не email.
- History фиксирует изменения текста и метаданных, выполнение и повторное открытие после установки обновления. Старую историю восстановить невозможно; фото в версии истории не дублируются.
- Сотрудник меняет пароль с проверкой текущего пароля, цвет аватара, тему интерфейса и срок напоминаний. Тема сохраняется в профиле Firebase.
- Admin и Boss управляют командой. Владелец защищён от удаления. Удаление через серверную функцию освобождает логин в Firebase Auth, сохраняя авторство заметок.
- Редактор не закрывается по клику вне окна. Кнопки закрытия и переход к другому дню спрашивают перед потерей изменений. Браузер предупреждает при перезагрузке с несохранённым текстом. При ошибке сохранения текст остаётся в редакторе.
- Одновременное редактирование одной заметки обнаруживается по номеру версии; более новая запись коллеги не перезаписывается молча.

## Установка

1. Загрузить изменённый index.html и папку assets в существующий репозиторий. Сохранить прежний способ GitHub Pages публикации.
2. Опубликовать новые Firestore Rules из firestore.rules в Firebase Console. Без них новые профили, упоминания и история могут получить отказ доступа.
3. Для автоматического удаления чужих аккаунтов развернуть серверную функцию. Нужен Firebase CLI, доступ владельца проекта и включённая возможность развёртывания Cloud Functions (обычно тариф Blaze). В корне проекта:

```sh
npm --prefix functions install
firebase login
firebase deploy --project kd-handover --only firestore:rules,functions:removeTeamMember
```

Никакие сервисные ключи в HTML, GitHub или файлы проекта добавлять не нужно. До развёртывания функции кнопка удаления покажет ошибку; она не подменяет удаление аккаунта простым удалением профиля.

4. Загрузить подготовленный чек-лист в документ printTemplates/nightChecklist через авторизованный доступ Firebase. Не добавлять внутренние инструкции в публичный GitHub.

5. Назначить управляющим точные роли Admin или Boss. Остальные роли не дают прав управления.
6. Проверить вход сотрудника, создание заметки, History, печать обоих бланков и задач по отделам. На тестовом сотруднике проверить удаление и создание нового аккаунта с прежним логином.

Изменения подготовлены без доступа к рабочим данным и без входа в аккаунты сотрудников. Проверка настоящих Firebase операций требует развёртывания и авторизованной сессии.
